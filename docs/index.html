01

What the code actually did

The augmentation step needed two views of the same folder: augmented images to train on, clean images to validate against. It built them with two separate splits.

# train and val are drawn from two different shuffles of the same 600 files full_dataset_aug = ImageFolder(root=data_path, transform=train_transform_aug) train_dataset_final, _ = random_split(full_dataset_aug, [train_size, val_size]) full_dataset_clean = ImageFolder(root=data_path, transform=val_transform) _, val_dataset_final = random_split(full_dataset_clean, [train_size, val_size])

Two unseeded shuffles → two different permutations → ~80% of the validation set is also in the training set.

Neither call is seeded, so each produces its own permutation. Roughly four out of five validation images were also being trained on. The notebook even flagged it in a comment — “hacky but works for this scope” — which is how most leaks get committed: noticed, downgraded, shipped.

The fix is to split the indices once and reuse them, so the two datasets differ only in transform.

g = torch.Generator().manual_seed(SEED) perm = torch.randperm(len(full_dataset), generator=g).tolist() train_idx, val_idx = perm[:train_size], perm[train_size:] train_dataset_final = Subset(dataset_aug, train_idx) # augmented val_dataset_final = Subset(dataset_clean, val_idx) # clean assert not (set(train_idx) & set(val_idx)) # Overlap: 0

Both cells now print their overlap. A leak that can reappear silently will.

02

What it was worth

We re-ran all eight experiments on the corrected split. Experiments 5–8 used the leaking loaders; 1–4 never did, and their movement is just reseeding noise.

The pattern

The leak only paid out to models that could memorize. Experiments 6 and 8 reached 94–96% training accuracy and lost 22 points when the overlap was removed. Experiment 5 — the same leaking loaders, but with dropout and augmentation holding it to 70% training accuracy — lost nothing. It had no capacity left to memorize the answers it was being shown.

Which means the run that looked worst was the only one telling the truth.

04

Rebuilding it honestly

A 120-image validation set makes single-split results almost unreadable — one image moves the number by 0.83 points, and picking the best of 15 epochs is itself a way of fitting the test set. So we rebuilt the evaluation before touching the model: 5-fold stratified cross-validation over all 600 images, every image predicted exactly once by a model that never trained on it, with horizontal-flip test-time augmentation.

Then we changed one thing at a time.

Two findings, both larger than the noise band.

05

What we'd tell the next person

Print the overlap, not the accuracy

Every split should assert its own disjointness and say so out loud. One assert would have caught this on the first run instead of the fiftieth.

A result that beats your baseline by 19 points is a bug report

The from-scratch notebook appeared to beat a fine-tuned ResNet34 by nineteen points. That was the tell, and we read it as success for weeks.

Fix the measurement before the model

On 120 validation images, nothing under about 8 points apart is distinguishable. Half our "findings" were coin flips until cross-validation replaced them.

Overfitting is a smoke alarm for leakage

96% train against 70% validation is a data-starvation signature. When that gap suddenly closes without new data, suspect the split before celebrating.
